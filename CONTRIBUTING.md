# Контрибьютинг

## Задача: теги каналов/постов

Нужно добавить систему **тегов** — маркировать каналы (и/или посты) тематическими метками
(например: `backend`, `frontend`, `ml_ai`, `devops`, `qa`, `career`) и использовать их в парсинге
и в публикации дайджеста.

### Где это живёт
- **Схема БД** — функция `db()` в `tgauto.py`: таблица `channels` уже имеет `cls` и `subtopic`.
  Теги — это либо новая таблица `tags(channel_id, tag)` (many-to-many), либо колонка. Реши сам,
  обоснуй в PR.
- **Проставление тегов** — новая команда в `tgauto.py` (по образцу существующих команд:
  `discover`, `parse`, `active`). Можно правилами (по ключевым словам в описании/постах)
  и/или через LLM-классификацию.
- **Публикация** — `digest_tg.py`: показывать теги в дайджесте и/или фильтровать топ по тегу.

### Как запустить локально
```
pip install -r requirements.txt
cp config.example.json config.json     # свой bot_token и т.д.
python tgauto.py selfcheck             # оффлайн-проверка логики (без аккаунтов)
```
Для работы с реальными данными нужны свои `accounts.json` и `data.db` — они НЕ в репо.
Разработку тегов можно вести на тестовой `data.db` (создаётся автоматически при первом запуске).

### Правила
- **Никаких секретов в коммитах.** `config.json`, `accounts.json`, `*.session`, `data.db` — в `.gitignore`.
- Стиль как в существующем коде (тот же уровень комментариев, именование, идиомы).
- Оставь одну запускаемую проверку логики (в духе `selfcheck`), если добавляешь нетривиальную ветку.
- Открывай PR — посмотрим и, если ок, вмёржим.
